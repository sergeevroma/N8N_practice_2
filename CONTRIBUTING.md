# Участие в Tiny Notes

Можно сообщать об ошибках, предлагать новые возможности, задавать вопросы и
отправлять Pull Requests. Перед созданием обращения прочитайте
[README.md](README.md) и проверьте, нет ли похожего Issue.

## Сообщение об ошибке

Опишите, какое существующее поведение работает неправильно. Укажите:

- Версию Python (`python3 --version`) и операционную систему.
- Точные команды воспроизведения и необходимые тестовые данные.
- Ожидаемый результат.
- Фактический результат и текст ошибки, если он есть.

Пример:

```text
Заголовок: Search misses notes with different letter case

В новом хранилище выполнил:
python3 notes.py --file bug-notes.json add "Buy Milk"
python3 notes.py --file bug-notes.json search "milk"

Ожидаю: #1: Buy Milk, поскольку поиск должен игнорировать регистр.
Фактически: Совпадений нет.
При поиске "Milk" заметка находится.
```

Вместо личных заметок приложите минимальные вымышленные данные.

## Предложение новой возможности

Опишите задачу пользователя, предлагаемое поведение и пользу изменения.
Добавьте пример команды и ожидаемого результата. Укажите, чем текущих команд
недостаточно для вашего сценария.

Пример:

```text
Заголовок: Add Markdown export

Хочу сохранять заметки в Markdown, чтобы вставлять их в учебные отчёты.
Сейчас программа только показывает заметки в терминале.

Предлагаю команду:
python3 notes.py export --format markdown --output notes.md

Ожидаю файл, в котором каждая заметка записана отдельным пунктом списка.
```

Пример описывает предлагаемую функцию: команды `export` в текущей версии нет.

## Вопрос по использованию

Расскажите, что хотите сделать, какие команды пробовали и какой раздел
документации вызвал затруднение. Вопрос об уже существующей возможности можно
оформить обычным Issue.

Пример:

```text
Заголовок: How can I keep study and personal notes separately?

Хочу хранить учебные и личные заметки в разных JSON-файлах.
Как выбрать файл для команд add и list?
Аргумент --file нужно указывать перед командой или после неё?
```

## Pull Requests

1. Для изменения поведения сначала создайте или найдите соответствующий Issue.
2. Делайте одно законченное изменение в одном PR.
3. Сохраняйте проект простым: стандартной библиотеки достаточно для текущих команд.
4. Обновляйте README, если меняются команды или поведение программы.
5. Проверьте затронутые сценарии на отдельном JSON-хранилище и опишите результат в PR.

Минимальная проверка перед PR (используйте новое хранилище):

```bash
python3 notes.py --file check-notes.json add "Read chapter 2"
python3 notes.py --file check-notes.json list
python3 notes.py --file check-notes.json search "chapter"
```

Добавление должно создать заметку `#1`; список и поиск должны показать
`#1: Read chapter 2`. Для исправления ошибки поиска дополнительно проверьте
поиск слов с разным регистром. Для новой команды покажите её запуск и результат.

## Общение и данные

- Пишите по существу и уважительно отвечайте другим участникам.
- Не публикуйте пароли, токены и реальные личные заметки.
- Не добавляйте локальные хранилища и виртуальные окружения в PR.
